# 风刃F9 蓝牙协议（离线参考）

本文件是逆向结论的完整版本，不依赖任何工具即可阅读。所有字节均来自
`LEGION EDGE.exe` 的代码 + 官方程序自己写的两份日志的相互印证。

---

## 1. 通道与帧格式

### 1.1 BLE 线上帧：20 字节定长

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 1 | `0xEE` 帧头 |
| 1 | 1 | CMD |
| 2 | 1 | SUB |
| 3 | 2 | ARG16，小端 |
| 5 | 15 | DATA |

### 1.2 USB HID 帧：30 字节（同一套协议）

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 1 | Report ID = `0x04` |
| 1 | 2 | 校验和 = `sum(bytes[3..63]) & 0xFFFF`，小端 |
| 3 | 1 | CMD |
| 4 | 1 | SUB |
| 5 | 2 | ARG16，小端 |
| 7 | 1 | 保留（恒 0） |
| 8 | 22 | DATA |

### 1.3 两者换算

```
ble[0]      = 0xEE
ble[1..4]   = usb[3..6]          // CMD, SUB, ARG16
ble[5..19]  = usb[8..22]         // 丢掉 usb[1..2] 校验和 与 usb[7] 保留字节
```

反向（收通知时）：把 8/20 字节的 BLE 通知补回 30 字节缓冲——

```
内部[0]=ble[0]  内部[1..2]=00 00  内部[3]=ble[1]  内部[4]=ble[2]
内部[5..6]=ble[3..4]  内部[7]=00  内部[8..]=ble[5..]
```

> 校验和规则已用 `NeoUsb.log` 里全部 2450 条 `Out:` 帧验证通过（2450/2450）。

## 2. 命令表

| CMD | SUB | 方向 | 说明 | 备注 |
|---|---|---|---|---|
| `0x03` | `0x22` | 写 → 读 | 连接握手 | 回复 `AA 55 00 00 06 80 18 00 02 08 01 00` |
| `0x06` | `0x0F` | 写 | 设置灯光 + 风扇 | 设备把 20 字节**原样回显**作为 ACK |
| `0x05` | `0x0F` | 写 → 读 | 读回当前灯光配置 | 回复与设置帧同形状 |
| `0x1A` | `0x06` | 写 → 读 | 状态轮询 | 回复只有 8 字节 |

时序（官方 App 的实际节奏）：

- 状态轮询：每 **3 秒**一次
- 设置帧：每 **6 秒**重发一次（保持状态）
- 连接后：先 `03/22` 握手，再 `05/0F` 读一次灯光

## 3. 设置帧（0x06 / 0x0F）

```
ee 06 0f 00 00 00 03 09 02 00 00 ff ff ff 00 00 00 00 01 00
              └┬┘ │ │ │ │  │  └──┬───┘ └───┬───┘ │  │  └── 恒 0
               │  │ │ │ │  │     │         │     │  └── LightSum（颜色数量，默认 1）
               │  │ │ │ │  │     │         │     └── 恒 0 ×4
               │  │ │ │ │  │     │         └── R G B
               │  │ │ │ │  │     └── 恒 0 ×2
               │  │ │ │ │  └── Speed   风扇档位（安静/平衡/野兽/超能）
               │  │ │ │ └── Light     亮度 1..9（原样下发）
               │  │ │ └── 恒 0
               │  │ └── SelectItem  灯光模式（恒亮/呼吸/渐变/动态光效）
               │  └── 恒 0
               └── ARG16 = 0
```

对应关系来自 `DefaultData.json` 里 `fan_F9` 的
`LightInfo{SelectItem:3, Light:9, Speed:2, Red:255, Green:255, Blue:255}`——
正好是上例的 `03 09 02` 与 `ff ff ff`。

> **更正（2026-10-28 真机核对）**：早期把 `data[2]` 判成 Fanmode 是错的，它是 Light（亮度）。
> 证据：官方日志 `2026-09-15-22-10-13:SetFanLightBrightness 1` 之后发出的帧是 `00 03 01 02`；
> 本机设备亮度 9 时读回 `00 03 09 02`。2448 条设置帧里没有出现 Fanmode 字节。

### 已观察到的 4 种变体（共 2448 次发送）

```
... 00 00 00 00 00 00     x1091   末字节组 = 00
... 00 00 00 00 01 00     x1159   末字节组 = 01（最常见）
... 00 00 00 00 02 00     x155    末字节组 = 02
... 00 00 00 00 03 00     x43     末字节组 = 03
```

第 18 字节（`LightSum` 位置）在 00–03 之间变化，其余字节在整个日志里恒定。

## 4. 状态回报（0x1A / 0x06）

BLE 上设备只回 **8 字节**：

```
ee 1a 06 00 00 01 LO HI
                  │  └──┬──┘
                  │     └── 转速 × 4（小端 16 位）
                  └── 状态：01 = 有效
```

```
转速 RPM = ((HI << 8) | LO) / 4
```

官方程序里对应代码：`rpm = (u32 & 0xFFFF) >> 2`，显示时再四舍五入到百位
`((rpm + 50) / 100) * 100`。

USB 通道下设备会回满 30 字节，后面还有温度等字段；**BLE 通道拿不到**。

实测样本（与官方日志里的 `FanRpm_Old` 逐条对得上）：

| 报文 | LE16 | 计算值 | 日志记录 |
|---|---|---|---|
| `27 1e` | 7719 | 1929 | 1929 |
| `66 19` | 6502 | 1625 | 1625 |
| `be 12` | 4798 | 1199 | 1199 |
| `b7 19` | 6583 | 1645 | 1645 |
| `a6 27` | 10150 | 2537 | 2537 |

## 5. 未解决的问题

| 问题 | 现状 |
|---|---|
| **亮度** | 已解决：`data[2]`，1..9 原样下发。实测写 5 后设备用 `ee 05 0f` 读回 `00 03 05 02`。 |
| **AI 模式与温度** | UI 文案说"根据电脑实时温度自动无级调节"。温度是 App 自己读 CPU 传感器，还是下发给散热器，尚未确认；2448 条设置帧里也没有独立的 Fanmode 字节。 |
| **多颜色 / 渐变** | 设置帧 `data[9..12]` 一直是 0，疑似是渐变/动态光效的额外颜色槽，未验证。 |
| **GATT 接口** | 必须打开按服务拆分的 `\\?\BTHLEDevice\{服务UUID}_Dev_…` 节点；总接口 `\\?\BTHLE\Dev_<地址>` 只能读缓存，读写一律 `0x80070001`。 |
| **GATT UUID** | 官方程序**不硬编码**服务/特征 UUID，而是枚举后按属性（可写 / 可通知 / 厂商自定义）挑选。F9 实测：服务 `19090909-…`、写 `19190909-…`、通知 `19290909-…`。 |

## 6. 抓包与自测建议

1. 用本工具发一帧，同时在官方 App 里点同一个按钮，对比两边十六进制。
2. 差异字节就是该功能的字段。
3. 官方日志位置：`%LOCALAPPDATA%\LEGION EDGE\BleC.log`（BLE 20 字节）和同目录 `NeoUsb.log`（USB 30 字节 + 解析后的语义日志）。
